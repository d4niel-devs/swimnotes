# Security policy

## Reporting a problem

Please report security problems privately, not in a public issue:
open the repository's **Security** tab and choose **Report a vulnerability**.

This is a small, personally maintained project. Reports are read as soon as reasonably possible, but there is no guaranteed response time.

## Supported version

Only the latest release and the `main` branch are supported.

## What the application does, in short

- It runs entirely in the browser. There is no server component, no account or sign-in, and no database.
- After the page has loaded it makes no network requests. The page's Content-Security-Policy enforces this (`connect-src 'none'`), and also allows scripts, styles, fonts and images only from the site itself.
- It stores nothing: no cookies, no local storage, no analytics.
- It contains no third-party code libraries. The only third-party files are four fonts and ten icons (see `THIRD_PARTY_NOTICES.md`).
- It builds comments from a fixed phrase bank included in the repository (`data/`). No text is generated by an outside service.

See `PRIVACY.md` for what happens to the names and notes a user types.

## Known limits

- The site is served by GitHub Pages, which does not let a project set its own HTTP response headers. The Content-Security-Policy is therefore delivered as a `<meta>` tag, which cannot include `frame-ancestors`; the page could be embedded in another site's frame. The page has no sign-in and no sensitive actions, so the impact is low. Hosting it somewhere that can set headers would close this.
- What users run is whatever is published at the time they load the page. Anyone who needs a fixed version can use a tagged release (for example `v1.0.0`) and host that exact copy themselves.
